# Comprehensive Fix Plan: MIME Type Script Failure, Endless Loading & Session Restoration

## Problem Analysis & Root Causes

Through an in-depth investigation across the codebase, build pipeline, service worker, and routing configurations, we have pinpointed four root causes behind the reported issues:

### 1. Root Cause for MIME Type `text/html` Error on `assets/app-*.js`
- **Vercel Catch-All Rewrite**: In `vercel.json`, `"source": "/(.*)", "destination": "/index.html"` rewrites missing asset requests to `index.html` with HTTP 200 `text/html`.
- **Service Worker Cache-First Navigation**: `public/sw.js` (generated by `vite.config.js`) used a **Cache-First strategy** for navigation requests (`/app/index.html`). After a new deployment with new asset hashes, returning stale cached HTML made the browser request old, deleted JS chunks (e.g. `app-xkNpIlpr.js`). Because Vercel replied with HTML, the browser threw:
  `Failed to load module script: Expected a JavaScript-or-Wasm module script but the server responded with a MIME type of "text/html".`
- When the main JS module failed to load, no JavaScript executed, leaving `#initial-loader` permanently frozen on the screen.

### 2. Root Cause for Maintenance Mode Toggle-Off Freeze
- **Element ID Mismatch**: In `js/auth.js`, `showMaintenanceScreen()` creates an overlay with `id="maintenance-screen"`. However, in `js/realtime.js`, the toggle-off listener checked `document.getElementById('maintenanceModal')`. Because the ID was wrong, the maintenance screen was never dismissed.
- Furthermore, `showMaintenanceScreen()` never called `hideInitialLoader()`, so the initial loading spinner stayed trapped in the background or foreground.

### 3. Root Cause for Endless "Initializing BMS..." Loader
- **No Failsafe Timeout on `#initial-loader`**: If any script, network request, or Supabase call timed out or threw an uncaught error before `hideInitialLoader()` was reached, the full-screen loader (`z-index: 10000`) remained stuck forever.
- In `js/auth.js`: Several return/error paths (`_showFatalAuthError()`, `showMaintenanceScreen()`, expired session logouts) failed to call `hideInitialLoader()`.

### 4. Root Cause for App Resume & Reconnect Failures
- **Blocking Session Refresh on Resume**: In `js/lifecycle.js`, `supabase.auth.refreshSession()` on tab focus/visibility change would occasionally hang or throw an offline error, causing view recovery to freeze.

## Proposed Changes

### 1. Build Pipeline & Service Worker Fix ([vite.config.js](file:///d:/v2%20BMS%20OFFICIAL/vite.config.js))
- **Network-First Navigation Strategy**: Update the Service Worker generation in `vite.config.js` so navigation requests (`request.mode === 'navigate'`) are **Network-First with a 2.5s network timeout**, falling back to cached HTML only when completely offline.
- Ensure new deployments immediately serve the fresh HTML with matching JS chunk hashes.

### 2. Vercel Routing Configuration ([vercel.json](file:///d:/v2%20BMS%20OFFICIAL/vercel.json))
- Explicitly exclude `/assets/(.*)` from the fallback HTML rewrite so missing assets return 404 instead of `text/html`.

### 3. Self-Healing Script Error Recovery & Failsafe Loader ([app/index.html](file:///d:/v2%20BMS%20OFFICIAL/app/index.html), [index.html](file:///d:/v2%20BMS%20OFFICIAL/index.html))
- Add an inline self-healing error handler in `<head>`: If a stale module script or MIME error occurs, automatically purge outdated caches and reload the fresh build.
- Add an inline **5-second failsafe timer** on `#initial-loader`: If the loader is still visible after 5 seconds, automatically fade it out and transition to the login or recovery screen so the user is never stuck.

### 4. Maintenance Screen & Realtime Synchronization ([js/auth.js](file:///d:/v2%20BMS%20OFFICIAL/js/auth.js), [js/realtime.js](file:///d:/v2%20BMS%20OFFICIAL/js/realtime.js))
- Unify maintenance overlay ID to `maintenance-screen` across both `auth.js` and `realtime.js`.
- Export `window.hideMaintenanceScreen()` to smoothly dismiss the maintenance overlay and restore active views when maintenance mode is turned off.
- Ensure `showMaintenanceScreen()` immediately calls `hideInitialLoader()`.

### 5. Resilient Auth & Lifecycle Session Restore ([js/auth.js](file:///d:/v2%20BMS%20OFFICIAL/js/auth.js), [js/lifecycle.js](file:///d:/v2%20BMS%20OFFICIAL/js/lifecycle.js))
- Guarantee `hideInitialLoader()` is invoked in every execution path of `initAuth()`, including `_showFatalAuthError()`.
- Add a retry CTA button on fatal auth error screens instead of locking the page.
- In `js/lifecycle.js`, protect `handleAppResume` with a 3-second non-blocking timeout that preserves cached offline sessions when offline or slow.
